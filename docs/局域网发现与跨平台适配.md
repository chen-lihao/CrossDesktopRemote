# 局域网发现与跨平台适配

> 状态：Apple 原型已实现；Windows 原生适配已编码，待 MSVC 与跨设备验收
> 服务类型：`_cdrremote._tcp`  
> 适用范围：同一局域网内发现可连接的 CrossDesktopRemote 被控端

## 1. 目标与边界

局域网发现只用于减少手工输入 IP 地址，不是身份认证或授权机制。发现设备后仍必须通过短时、单次消费的六位连接码；正确连接码本身授权本次有人值守会话，不再增加第二次被控端点击确认。

强制边界：

- 不在 DNS-SD TXT 记录中发布房间码、密码、token 或用户账号。
- 不扫描整个 IPv4 子网；使用各平台的 DNS-SD/mDNS 系统 API。
- 必须保留手动地址输入，用于 VLAN、企业 Wi-Fi、VPN 和禁止组播的网络。
- 被发现设备与信令服务器是两个独立概念；不得将被控设备主机名直接当成信令服务器地址。
- 发现结果不自动连接。用户主动选择设备后，空地址、回环地址或与设备不同的信令配置会切换为广播中经校验的非敏感 rendezvous URL；相同配置保留用户当前填写的规范地址。
- DNS-SD 不提供“信令服务器目录”。独立公网信令服务器通常不在终端局域网内，也不应通过 mDNS 发布；它由正在等待连接的被控端在 `signalUrl` 中声明。

## 2. 统一抽象

Flutter 层只依赖 `LanDiscoveryService`：

```text
LanDiscoveryService
├── watch devices
├── start/stop browsing
└── publish/stop host
    ├── Apple DNS-SD
    ├── Android NsdManager
    ├── Windows DNS Service Discovery
    └── Linux Avahi
```

当前接口位于 `apps/client_flutter/lib/core/discovery/lan_discovery_service.dart`。平台实现不能将 DNS-SD 回调、原生句柄或网络接口细节暴露给业务 UI。

TXT v2 字段：

| 字段 | 用途 | 约束 |
| --- | --- | --- |
| `id` | 发现列表去重 | 当前为本机名，后续替换为稳定设备 ID |
| `v` | 发现协议版本 | 当前为 `2` |
| `path` | WebSocket 路径 | 当前为 `/ws/signaling` |
| `cap` | 非敏感能力提示 | 当前为 `screen,pointer` |
| `platform` | 被控端平台 | `macos` / `windows` 等 |
| `signal` | 信令配置非密钥指纹 | 仅用于检测两端是否使用同一配置 |
| `signalUrl` | 非敏感 rendezvous URL | 可以指向 Mac 局域网服务或独立公网 `wss` 服务，不含连接码 |

## 3. 平台任务矩阵

| 平台 | 系统 API | 发布 | 发现 | 当前状态 | 待完成任务 |
| --- | --- | --- | --- | --- | --- |
| macOS | Apple DNS-SD | 被控端等待时发布 | 预留 | 已编码并通过 Debug 构建 | 双设备发布/消失时延验收；设备 ID 持久化 |
| iOS/iPadOS | Apple DNS-SD | 不发布 | 控制端浏览并解析 | 已编码并通过 Simulator 构建 | 物理 iPad 权限、多网卡、网络切换验收 |
| Android | `NsdManager` | 仅被控模式需要 | 控制端发现/解析 | 未开始 | 实现 MethodChannel；兼容 MulticastLock；为 Android 17+ 评估系统服务选择器与 `ACCESS_LOCAL_NETWORK` |
| Windows | `DnsServiceBrowse`/`DnsServiceRegister` | PC 被控端等待时发布 | 控制端浏览并解析 | 已接入 Runner，待 Windows 构建/实机验收 | MSVC `/WX`构建；Mac↔Windows互相发现；网卡变更、睡眠唤醒、防火墙和Windows 10/11矩阵 |
| Linux | Avahi client API/DBus | PC 被控端发布 | 控端发现 | 未开始 | 检测 Avahi daemon；实现插件；无 Avahi 时降级手动输入 |

Android 使用官方 `NsdManager` DNS-SD，参考 [Android NSD 文档](https://developer.android.com/develop/connectivity/wifi/use-nsd)和 [NsdManager API](https://developer.android.com/reference/android/net/nsd/NsdManager)。Windows 使用 Windows 10+ 的 [DNS Service Browse API](https://learn.microsoft.com/windows/win32/api/windns/nc-windns-dns_service_browse_callback)。

## 4. 生命周期

- Mac 信令连接进入 `waitingForPeer` 后发布。
- 控制端加入、用户断开、信令失败或应用退出时撤销发布。
- iPad 设备页挂载后开始发现；应用退出时停止。
- 信令服务器配置使用 `SharedPreferencesAsync` 持久化，切换控制/被控角色不得重置为 `127.0.0.1`。
- 网络变更后需要刷新发布与解析结果，不持久化 IP 地址。
- Windows 原生异步回调只在 UI 线程提交 Flutter 事件；停止浏览时取消 Browse/Resolve，停止共享时异步注销服务并释放 WinDNS 返回的实例。

## 6. 安全与后续升级

mDNS 可被同网段设备伪造。当前局域网原型依靠连接码 TTL、单次消费和失败限流降低直接接入风险；发现数据本身不授予权限。正式设备体系建立后，TXT 中只发布设备 ID 与协议版本，真实身份由设备证书、短期票据和加密会话验证。
