# iPad 控制 Mac 色彩验收

本文用于物理验证 macOS ScreenCaptureKit SDR/Rec.709 采集、iPad 显示调整、HDR A/B 和多显示器独立设置。自动测试只能验证配置、协议和颜色矩阵，不能判断真实面板观感或已经发生的高光裁切。

## 1. 准备

1. 使用最新版 Mac 和 iPad Debug 应用建立远程会话。
2. Mac 准备普通桌面内容、SDR 灰阶图、HDR 视频，并连接可用的扩展显示器。
3. iPad 点击远程工具栏的“显示调整与色彩诊断”图标。
4. 初始模式保持“自动”，Mac 系统 HDR 保持当前日常设置。

## 2. 分阶段诊断

刷新色彩诊断。诊断只传输抽样统计、格式和附件，不保存或上传屏幕像素。使用同一灰阶画面比较以下检查点：

| 检查点 | MVP 期望 | 实际值 |
| --- | --- | --- |
| ① ScreenCaptureKit 原始帧 | 记录真实格式、Range、primaries、transfer、matrix 和 Y 直方图；不得被代码预先改写 |  |
| ② WebRTC 编码器输入 | `420v/NV12`、Video Range、BT.709；由 Core Image/Metal 实际转换，Y 通常处于 16～235 |  |
| ③ iPad 解码输出 | 原生 `420v` 或 I420；Y 分布应与②基本一致，不应在高光端突然集中 |  |
| iPad Texture 输入 | sRGB BGRA；转换方式显示 Core Image 或 vImage BT.709，不应显示 compatibility fallback |  |
| WebRTC 目标 / 发送 / 接收 | 三者尺寸相同或仅存在不超过 2 像素的编码对齐；不得把 `1311×892` Sidecar 无意义放大为 `1920×1080` |  |
| Mac 色彩归一化 | `Core Image GPU HDR→SDR · Rec.709 · Video Range NV12` |  |
| 当前/潜在 EDR headroom | 与当前 Mac 显示器状态一致 |  |

每个检查点同时显示 `Y min～max`、标称黑白位、越界比例和16桶直方图。诊断显示 `Unknown` 时，等待远程画面稳定后再次刷新。

按以下规则定位：

- ①已经泛白或高光集中：问题在 ScreenCaptureKit/显示器动态范围输入。
- ①正常、②异常：问题在 Mac Core Image 归一化。
- ②正常、③异常：问题在 WebRTC 编码、H.264 VUI 或 iPad 解码。
- ②尺寸正确但 WebRTC 发送尺寸错误：问题在切屏后的 Sender/编码器重配置；记录三组尺寸和切换序号。
- WebRTC 发送正确但接收或 Texture 尺寸错误：问题在 iPad 解码或 Renderer 尺寸回调。
- ③正常、Texture 输入异常：问题在 iPad Range/矩阵转换。
- 四处统计均正常但肉眼仍泛白：检查 Flutter/系统合成、iPad 原彩显示、夜览和面板设置。

## 3. SDR 灰阶与普通桌面

1. 点击“在 Mac 显示灰阶图”。
2. 在 iPad 的远程画面中检查 0～219 基础灰阶以及 235、239、243、247、251、255 高光格。
3. 重点确认 235～255 不会全部变成同一块纯白，暗部也没有大面积压成纯黑。
4. 打开 Finder、Safari、文本编辑和带渐变的普通 SDR 图片，检查白底、灰色边框、肤色及彩色图标。
5. 刷新诊断，保存四个检查点的格式、Y范围、越界比例和16桶直方图到下方验收记录。

| 检查项 | 通过条件 | 结果 |
| --- | --- | --- |
| 暗部 | 相邻暗阶仍可区分 | `[ ]` |
| 235～255 高光 | 至少主要相邻格保持可区分，不大面积裁切 | `[ ]` |
| 白色桌面 | 不出现明显整屏泛白或灰雾 | `[ ]` |
| 彩色内容 | 无明显偏色或过饱和 | `[ ]` |

## 4. HDR 开关 A/B

1. 保持同一显示器、远程画面、画质档位和网络不变。
2. 点击“打开 Mac 显示器设置”，临时关闭 HDR，刷新色彩诊断并记录截图/现象。
3. 重新开启 HDR，再次刷新诊断并观察同一普通桌面、HDR 视频和灰阶图。
4. 两种状态下 iPad 都不应出现明显整屏泛白或高光大面积裁切。

关闭 HDR 只用于定位问题，不作为正式使用要求。若显式 SDR 管线在 HDR 开启时仍失败，记录 Mac 型号、显示器、macOS 版本、诊断字段和复现素材，再进入 Metal/Core Image HDR→SDR tone mapping 阶段。

## 5. 显示调整与多显示器

1. 在主屏选择“柔和高光”，确认画面观感立即变化，但灰阶中已经合并的纯白无法被恢复。
2. 切换“自定义”，分别调整亮度、对比度、饱和度，确认无重连即可生效。
3. 切换到扩展屏，设置一组不同参数。
4. 在主屏与扩展屏之间往返切换，确认各自设置独立恢复。
5. 分别点击“恢复当前显示器默认值”，确认只重置当前显示器。
6. 将 iPad 作为 Mac Sidecar 扩展屏，在远程控制端全屏切换主屏与 Sidecar；每次等待切换进度图标消失。
7. 连续往返切换 30 次，确认 PeerConnection、DataChannel 和连接码保持不变，左上角名称、远程画面和色彩设置始终属于同一显示器；不得出现 `peer-left` 或重新连接提示。
8. Sidecar 使用“完整适应”时，确认画面水平、垂直居中，上下黑边差值不超过 2 个逻辑像素。
9. 刷新诊断，确认 Sidecar 的 WebRTC 目标、发送、接收尺寸一致或仅有编码对齐差异；若原始采集为 `1311×892`，不得显示为发送端主动放大的 `1920×1080`。
10. 点击画面中心和四角，确认指针映射仍与居中后的视频内容矩形一致。
