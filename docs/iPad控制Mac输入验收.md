# iPad 控制 Mac 输入验收

本文用于验收 iPad 触控、远程鼠标和中文输入。自动测试只能覆盖状态机和协议；手感、系统输入法候选以及画面反馈延迟必须在物理 iPad 与 Mac 上确认。

## 1. 准备

1. Mac 和 iPad 连接同一局域网，启动 Java 信令服务和两端应用。
2. Mac 选择“共享本机”，确认屏幕录制和远程输入权限均已授予。
3. iPad 连接 Mac，在工具栏的“更多”菜单中确认可以打开“操作说明”和“输入设置与诊断”。
4. Mac 打开“文本编辑”和 Safari 普通文本框。密码框、安全输入框不作为 Unicode 注入验收目标。

## 2. 直接触控

| 操作 | 预期结果 | 结果 |
| --- | --- | --- |
| 单指轻点 | Mac 左键单击触点对应位置 | `[ ]` |
| 双击 | Mac 完成双击；文本中选择单词 | `[ ]` |
| 按住拖动 | 窗口可拖动；文本可连续选择 | `[ ]` |
| 双击第二下按住拖动 | 按单词扩展文本选择 | `[ ]` |
| 双指轻点 | Mac 打开右键菜单 | `[ ]` |
| 双指滑动 | 页面连续滚动，不误触右键 | `[ ]` |
| 静止长按后松开 | 作为备用操作打开右键菜单 | `[ ]` |

连续移动和拖动 10 秒，观察鼠标是否持续落后、过冲或与手指位置逐渐偏离。稳定偏差通常属于坐标映射问题；随操作时间增大的偏差通常属于事件积压问题。

## 4. 拼音与 Unicode 输入

1. iPad 打开远程键盘并切换到系统简体拼音。
2. 确认键盘栏显示“即时远程键盘”，且不存在持续累积历史文字的输入框。
3. 依次输入并选择候选：`你`、`你好`、`中文输入测试`；选择完整候选后不按空格或退格。
4. 验证 Mac 立即且仅收到一次最终汉字，不收到 `nihao`、零宽字符或重复候选。
5. 连续输入 100 组中文，检查丢字、重复和顺序。
6. 在 Mac 主动删除部分文字、移动光标，再从 iPad 输入和连续退格 50 次；确认退格始终有效且 iPad 不出现历史文本失配。
7. 验证中英文混排、数字、全角/半角标点、emoji、软键盘回车以及外接硬件键盘。
8. 长按软键盘退格，确认 Mac 连续删除且松开后立即停止。
9. 点击键盘栏右侧“整句发送”，完成一整句候选选择后发送，确认兜底路径正常并在发送后清空。
10. Debug 版本可打开键盘栏“输入法事件诊断”；确认只包含事件名称、长度和 CJK 标记，不包含实际输入内容。
11. Debug 版本可在“输入设置与诊断”中点击“发送中文诊断文本”，Mac 应出现一次“你好”。

如果诊断文本成功但系统拼音失败，保存“输入法事件诊断”结果并记录输入法名称；如果诊断文本也失败，再检查 Mac 远程输入权限和目标应用是否接受 Core Graphics Unicode 事件。密码框、安全输入框和部分自绘控件不作为通用 Unicode 注入承诺。

## 5. 延迟与事件积压

“输入设置与诊断”每 30 个移动事件采样一次输入往返延迟，并显示因发送缓冲过高而丢弃的过期移动数量。

- 局域网输入往返延迟应稳定，阶段目标 P95 不高于 80ms，优化目标不高于 60ms。
- 正常局域网操作中，丢弃数量应保持为 0 或只在突发操作时少量增长。
- 指针移动按约 60Hz 合并；绝对位置保留最新值，相对移动和滚动累加位移。
- 如果延迟持续上升或丢弃数快速增长，记录 iPad/Mac 型号、分辨率、画质档位、网络和复现手势后再分析。
