# 诊断与日志

## 目标

诊断系统用于还原“建立连接、认证、媒体、输入、文件传输、断开和崩溃”的完整时序，不代替会话审计记录，也不改变远程控制协议。日志默认只保存在本机，只在用户主动导出时生成 `.cdrdiag` 诊断包，应用不会自动上传。

## 统一关联模型

- `traceId`：一次端到端连接链路的公共标识。控制端建立后由信令服务器转发给双端，仅用于诊断关联。
- `attemptId`：单端本次尝试的标识，重试、取消和失败后不复用。
- `sessionId`：已建立远程会话的稳定标识，与现有会话审计记录一致。
- `spanId`：预留给认证、WebRTC、文件传输等子事务。

Flutter 会话核心生成 `attemptId` 和初始 `traceId`；信令服务器配对成功后向双端发布同一 `connectionTraceId`。旧客户端未携带诊断字段时不会被拒绝，服务器使用匿名兼容标识。

## 事件模型

每条事件使用结构化 JSON，核心字段包括：

```text
schemaVersion, timestampUtc, monotonicMs, bootId, severity,
component, event, errorCode, traceId, attemptId, sessionId,
spanId, role, attributes
```

错误使用稳定错误码，例如 `CDR-SIGNAL-001`、`CDR-WEBRTC-STATS-001`、`CDR-FLUTTER-001`。用户可以复制错误码进行反馈，文案变化不会影响聚合。

当前已接入：

- Flutter 框架错误、Dart Zone 未捕获异常。
- WebSocket 连接、关闭、传输错误及消息类型/字节数，不记录消息正文。
- 会话尝试、状态转换、对端变化、文件传输状态。
- 详细模式下的 WebRTC 码率、丢包、RTT、掉帧、冻结、编解码器统计。
- Windows 现有 minidump 附件的主动导出。

## 隐私与安全边界

事件在进入内存队列和落盘之前必须通过统一脱敏器：

- 不记录连接码、密码、token、签名、挑战值、SDP、ICE candidate、剪贴板正文或屏幕内容。
- 机器码、设备 ID、IP/地址和文件路径使用本机加盐摘要替代，不保留可逆原文。
- 文件传输只记录方向、文件数、字节数和状态，不记录文件名与路径。
- `.cdrdiag` 可能包含 Windows minidump，内存转储仍应视为敏感资料；只应在用户明确操作后交给可信的开发人员。

诊断日志与加密 SQLite 会话审计是两个独立数据域。“清理诊断日志”不会删除会话历史、可信设备、设置或文件传输审计。

## 本地保留和导出

- 默认保留 7 天，单文件最大 5 MiB，最多 10 个分段。
- 内存中保留最近 256 条 breadcrumb。
- 普通模式不将 debug 事件落盘。
- 15 分钟详细诊断模式会自动过期，避免长期收集高频统计。
- 导出包使用 `.cdrdiag` 扩展名，包含脱敏事件、摘要和有界崩溃附件；最多收集 3 个、每个不超过 10 MiB 的崩溃文件。

“设置 → 诊断与日志”可以查看事件数量和保存位置、开启 15 分钟临时详细模式、导出诊断包或清理诊断日志。

## 当前边界与后续增强

当前版本完成了跨 Flutter/Java 的结构化事件、端到端关联、本地滚动保留、脱敏和用户主动导出。以下内容属于后续原生增强，未在当前版本中声称已完成：

- Windows Crashpad 独立崩溃进程、macOS/iOS MetricKit 与 PLCrashReporter。
- Rust `tracing` 向 Flutter 诊断中心的统一 FFI sink。
- 主线程卡顿看门狗与原生线程堆栈采样。
- 诊断包的接收方公钥加密和可选的自建上传端点。
- iPadOS 系统分享面板；当前 iPad 保留在应用管理目录，桌面端可直接选择导出位置。

## 验收要求

- 同一次连接的 Flutter 与 Java 记录可以通过 `traceId` 关联。
- 连续重试必须生成不同 `attemptId`，不得与上一次失败尝试混合。
- 日志中不得出现真实连接码、SDP、ICE candidate、剪贴板正文和原始文件路径。
- 日志写入失败不得中断媒体、输入、文件传输或信令。
- 关闭详细模式后，高频 WebRTC debug 统计不得继续落盘。
- 无网络时仍可以导出诊断包，且导出行为不会触发任何自动上传。
