# 远程系统音频

## 产品边界

远程系统音频使用与视频相同的 WebRTC PeerConnection，但作为独立的音频轨道协商和传输。它不属于某个显示器，因此主副屏切换只替换视频轨道，不重建或中断音频轨道。

当前范围：

- macOS 13 及以上被控端：使用 ScreenCaptureKit 采集系统播放声音。
- Windows 11 被控端：使用 WASAPI process loopback 采集当前会话的系统播放声音，并排除本应用进程。
- macOS、Windows、iPadOS 控制端：通过 WebRTC 原生音频设备播放远端声音，并提供本地静音开关。
- 不采集麦克风，不提供双向语音通话，不把 PCM 音频帧送入 Dart。
- DRM/受保护媒体可由操作系统返回静音，应用不得绕过系统保护。

## 用户授权与权限

被控端的“共享本机系统声音”是持久化总开关，默认关闭。关闭时即使对端支持音频，也不会启动原生音频采集。

动态连接码会话只受该总开关控制。可信设备会话还必须满足被控端为该设备授予 `listenSystemAudio` 权限；该权限不包含在默认可信权限中，并与查看屏幕、控制输入、剪贴板和文件权限相互独立。总开关或可信权限任一关闭，音频轨道均不发送媒体。

控制端的静音开关只关闭本机播放，不改变被控端授权、采集开关或另一控制端的策略。会话断开时必须停止原生采集、解除 Sender 轨道并释放 MediaStream。

## 能力协商

音频使用两个方向能力：

- `system-audio-capture-v1`：被控端能够采集系统播放声音。
- `remote-audio-playback-v1`：控制端能够播放远端音频轨道。

双方必须分别声明对应能力后才启动采集。可信会话的能力集合和 `listenSystemAudio` 权限继续参与现有授权摘要及签名 WebRTC Binding，信令服务不能增加权限或替换能力。旧客户端缺少任一能力时只关闭音频，视频、输入、剪贴板和文件传输继续按原协议运行。

## 媒体链路

```text
macOS ScreenCaptureKit / Windows WASAPI process loopback
                         │
                         ▼
              native 48 kHz stereo PCM
                         │
                         ▼
            WebRTC raw audio source / Opus
                         │
              same PeerConnection audio RTP
                         │
                         ▼
          controller native audio output device
```

Windows 采集与 WebRTC 送帧线程解耦，使用 10 ms 音频帧、有界环形缓冲和 100 ms 启动预缓冲，避免 WASAPI 批量回调直接扰动 WebRTC 音频线程。macOS 使用独立的 ScreenCaptureKit 音频流，经 WebRTC AudioDeviceModule 的输入图送入 raw 音频轨道。自动增益、回声消除和降噪均关闭，避免处理系统原声。

音频采集生命周期通过单一串行队列管理。快速开关、会话关闭和启动失败不能并发操作同一个原生采集器；旧 generation 的异步启动结果必须立即停止并释放。

## 验收清单

- [x] Flutter 能力、默认权限与设置持久化自动测试。
- [x] Rust 能力协商、权限位和旧客户端降级自动测试。
- [x] macOS Debug 构建、iOS 模拟器构建、Java 信令测试。
- [ ] Windows 11 + MSVC `/WX` 完成原生编译。
- [ ] Mac → Windows、Windows → Mac、Mac/Windows → iPad 各持续播放 30 分钟，无明显爆音、持续断音或音画漂移。
- [ ] 主副屏往返切换 30 次，音频不中断且不会重复创建音频轨道。
- [ ] 被控端默认不采集；关闭总开关、撤销可信音频权限或断开会话后立即停止采集。
- [ ] 控制端静音/恢复各 30 次，不触发重新协商，不影响视频和输入。
- [ ] 系统睡眠唤醒、默认输出设备切换和音频服务重启后，失败状态可诊断；自动恢复能力在完成目标平台真机验证前不得标记为已验收。
- [ ] 旧客户端连接时无音频，但原有远控能力不回归。

## 当前限制

- Windows 原生编译、WASAPI 设备变化和真实声卡行为只能在 Windows 真机验收。
- macOS ScreenCaptureKit 系统声音要求 macOS 13 及以上，并受屏幕录制权限和系统受保护内容策略约束。
- 当前只实现桌面系统声音下行；麦克风、语音聊天、Android/Linux 被控端音频采集不在本阶段范围。
- 睡眠、声卡热切换或底层音频服务重启后的无缝恢复仍需真机数据决定是否引入平台级重建策略，不能用定时重启采集器掩盖故障。
