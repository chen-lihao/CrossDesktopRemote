# 可信设备认证

## 产品边界

CrossDesktopRemote 只提供两种连接方式：

1. **可信设备免码连接**：设备完成一次人工确认后，以设备密钥完成后续认证。
2. **动态连接码连接**：保留现有六位、五分钟、单次消费流程，用于首次配对、信任过期和故障恢复。

可信认证失败时不得自动退回连接码。用户必须返回设备页，明确选择“使用连接码”，避免降级攻击。二维码、账号密码和永久共享密码不属于当前协议。

## 信任边界

- Java 信令服务仅按公开机器码提供临时在线路由，不保存私钥、`TrustGrant` 或最终授权状态。
- 更换信令服务器不会使已有可信关系失效；双方连接到同一服务即可继续认证。
- 局域网开发允许 `ws://`。设备身份、授权范围和完整 SDP 均位于端到端签名信封中，SDP 内的 WebRTC DTLS 指纹因此一并受保护。
- `ws://` 无法隐藏 IP、机器码、消息大小和连接时间，也无法阻止恶意网络或信令服务丢弃消息、延迟消息和拒绝服务。公网部署仍必须使用 `wss://`。
- Host 本地可信设备库是最终授权源；路由成功不等于授权成功。

## 设备身份

每台设备维护两层 P-256 密钥：

| 密钥 | 生命周期 | 用途 |
| --- | --- | --- |
| 根身份密钥 | 安装级长期稳定 | 派生机器码 v2、签发认证子密钥和可信授权 |
| 认证子密钥 | 30 天 | 签署高频会话消息，轮换时允许 7 天旧密钥重叠 |

Apple 平台使用 Secure Enclave/Keychain，Windows 使用 CNG/TPM；私钥以不可导出的原生 key handle 保存，不进入 Dart、SQLite、SharedPreferences 或信令服务。若平台无法提供受保护密钥，可信入口默认关闭，动态连接码仍可使用。

机器码 v2 从根公钥 SHA-256 指纹截断并附加校验得到，只承担路由和展示作用，不是密码。认证时必须校验完整根公钥指纹，不能只比较机器码文本。

## 首次配对

首次信任复用已建立的连接码 WebRTC 会话：

1. 双方交换根公钥、认证子密钥证书和各自随机数。
2. 双方基于会话 ID、根公钥指纹和随机数计算相同的六位 SAS 校验码。
3. 两端展示 SAS；Host 暂停远程输入，避免控制端代替本机用户确认。
4. Host 选择授权范围：查看屏幕为必选，键鼠、剪贴板、文件传输和自动续期分别控制。
5. 双方分别用根密钥签署包含最终权限位的确认内容。
6. Host 验证双方确认后签发方向明确的 `TrustGrant`，两端写入各自加密可信库。

任何身份变化、SAS 不一致、签名错误、权限内容变化或超时都会终止配对，不会产生半可信记录。

## 可信直连

控制端从本地可信列表选择 Host 后，通过机器码请求临时路由：

1. Java 为在线 Host 与 Controller 建立临时 `sessionId`，并与连接码会话共用单控制端仲裁。
2. Host 发送签名挑战；Controller 使用已持有的 `TrustGrant` 和签名响应。
3. Host 校验固定根身份、认证子密钥证书、授权有效期、撤销状态、请求权限、nonce、序列号和接收者指纹。
4. 双方交换签名 Offer/Answer；完整 SDP 受签名保护。
5. 只有本地授权通过后才开始采集、输入和数据通道功能。

签名信封使用 60 秒有效期、单调序列和一次性 nonce。防重放缓存有界，缓存耗尽时失败关闭并要求重建会话。原始签名 payload 上限为 32 KiB，为 Java 64 KiB JSON/WebSocket 上限预留 Base64、身份和签名开销。

连接码与可信路由共用 `HostSessionArbiter`：一个 Host 同时只能被一个 Controller 占用。Host 忙时不能消费仍有效的连接码。

## 权限与生命周期

`TrustGrant` 默认只有“查看屏幕”和“控制键鼠”，剪贴板与文件传输需要 Host 明确授权。运行期每条敏感链路继续检查授权，不因媒体会话已经建立而放行。

| 项目 | 默认值 | 行为 |
| --- | --- | --- |
| 签名会话票据 | 60 秒 | 超时或重放立即拒绝 |
| 认证子密钥 | 30 天 | 自动轮换，旧子密钥最多重叠 7 天 |
| 可信软租约 | 90 天 | 自动续期开启时，于剩余 14 天内在成功可信会话后续期 |
| 人工复核硬期限 | 365 天 | 不能自动越过，必须重新使用连接码配对 |

续期只能保留或缩小权限，不能改变根身份、扩大权限或延长原始硬期限。全局“暂停可信连接”和单设备撤销会立即执行本地门禁；活动可信会话会断开，动态连接码会话不受影响。

可信设备记录、授权、撤销墓碑、暂停状态和审计详情保存在 AES-GCM 加密 SQLite 中，数据库密钥由系统安全存储提供。审计记录配对、可信连接、续期、权限变化、过期和撤销，不记录私钥、签名原文、屏幕内容或剪贴板内容。

## 能力与兼容

可信链路通过以下能力协商隔离：

- `device-identity-v1`
- `trusted-device-auth-v1`
- `signed-webrtc-binding-v1`
- `trust-lease-renewal-v1`

新字段缺失即关闭对应能力。旧客户端继续使用连接码和既有 WebRTC 流程；可信连接不得因对端缺少能力而自动降级。

## 验收清单

- [ ] Mac、Windows、iPad 两两使用连接码配对，SAS 一致后才能生成可信记录。
- [ ] 篡改任一根公钥、SAS nonce、权限位、签名 SDP、接收者指纹、序列或有效期，连接均失败关闭。
- [ ] 同一签名消息重放 100 次均被拒绝，不能产生第二条会话或重复续期。
- [ ] 更换局域网信令地址后，原可信关系仍可直连；假冒相同机器码但不同根公钥的设备必须被拒绝。
- [ ] 可信直连连续 100 次；任何失败都不得自动改用连接码。
- [ ] 暂停全部可信连接、撤销单设备和软租约过期后立即拒绝新连接，并终止对应活动可信会话。
- [ ] 自动续期不扩大权限、不越过 365 天硬期限；关闭自动续期后 90 天到期必须重新配对。
- [ ] Host 已有连接码或可信会话时，另一认证方式返回忙；被拒绝的正确连接码仍可在 Host 空闲后使用。
- [ ] 可信授权没有剪贴板或文件权限时，相应通道保持关闭；动态连接码原有行为不回归。
- [ ] Windows 11 + TPM/CNG、macOS/iPadOS Secure Enclave 真机验证密钥不可导出、重装/密钥变化触发身份变化告警。

## 当前限制

- Windows 原生编译、TPM 行为和 Mac/Windows/iPad 跨平台物理验收必须在目标设备执行。
- 当前 Java 可信路由是单 JVM 内存实现，适用于局域网开发；公网多实例需要 Redis 路由、分布式限流、TLS 和 TURN 临时凭据。
- 恶意信令服务器仍可拒绝服务或暴露元数据，但不能在没有设备私钥和有效本地授权的情况下伪造可信端点。
