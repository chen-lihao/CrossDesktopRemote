# 可信设备认证

## 产品边界

CrossDesktopRemote 只提供两种连接方式：

1. **可信设备免码连接**：设备完成一次人工确认后，以设备密钥完成后续认证。
2. **动态连接码连接**：保留现有六位、五分钟、单次消费流程，用于首次配对、信任过期和故障恢复。

可信认证失败时不得自动退回连接码。用户必须返回设备页，明确选择“使用连接码”，避免降级攻击。二维码、账号密码和永久共享密码不属于当前协议。

## 信任边界

- Java 信令服务仅按公开机器码提供临时在线路由，不保存私钥、`TrustGrant` 或最终授权状态。
- 更换信令服务器不会使已有可信关系失效；双方连接到同一服务即可继续认证。
- 局域网开发允许 `ws://`。设备身份、授权范围和完整 SDP 均位于端到端签名信封中，SDP 内的 WebRTC DTLS 指纹因此一并受保护。
- `ws://` 无法隐藏 IP、机器码、消息大小和连接时间，也无法阻止恶意网络或信令服务丢弃消息、延迟消息和拒绝服务。公网部署仍必须使用 `wss://`。
- Host 本地可信设备库是最终授权源；路由成功不等于授权成功。

## 设备身份

每台设备维护两层 P-256 密钥：

| 密钥 | 生命周期 | 用途 |
| --- | --- | --- |
| 根身份密钥 | 安装级长期稳定 | 派生机器码 v2、签发认证子密钥和可信授权 |
| 认证子密钥 | 30 天 | 签署高频会话消息，轮换时允许 7 天旧密钥重叠 |

macOS/iPadOS 使用 CryptoKit Secure Enclave，Windows 使用 CNG/TPM。Apple 端只在 Keychain 中保存由 Secure Enclave 持有的不可导出密钥对象；Windows 端只保存 TPM 密钥句柄和由用户级 DPAPI 保护的本地数据密钥。明文私钥不进入 Dart、SQLite、SharedPreferences、普通文件或信令服务。若平台无法提供要求的硬件密钥，可信入口失败关闭，动态连接码仍可由用户显式选择。

平台密钥实现必须返回明确的身份状态，而不是以单个 `hardwareBacked` 布尔值隐藏失败原因：

- `readyHardwareProtected`：硬件密钥、自检和本地绑定全部通过，可以进行可信认证。
- `readyOsProtected`：只有操作系统密钥库保护；默认不能在要求硬件身份的平台上进行免码认证。
- `migrationRequired`：检测到旧版软件身份，必须经过用户确认升级。
- `keyMissing`、`identityMismatch`、`storageFailure`、`transientFailure`：全部失败关闭，并向用户提供对应恢复动作。

macOS 使用默认应用 access group 中的持久 Secure Enclave P-256 签名密钥。Keychain 条目是密钥对象的系统索引，不是可导出的私钥文件。根密钥和 30 天认证子密钥使用独立 application tag；根指纹固定在应用偏好中，启动时核对公钥、验证根签发的子密钥证书，并执行随机挑战签名自检。子密钥距过期 7 天时无感轮换。

macOS 非稳定签名（例如默认 ad-hoc Debug）构建通过 `CDR_TRUSTED_IDENTITY_MODE=disabled` 关闭可信身份，不访问 Keychain，也不回退到软件私钥。需要可信身份时，使用本地 `DeveloperSigning.xcconfig` 配置稳定 Personal Team/Apple Development 签名；该文件不入库。共享 `Runner.xcodeproj` 不得写入开发者 Team ID，避免本地配置被旧 Team 覆盖。

`hardware` 模式通过构建设置选择独立的 `HardwareIdentityDebugProfile.entitlements` 或 `HardwareIdentityRelease.entitlements`。其中 `keychain-access-groups` 使用 `$(AppIdentifierPrefix)$(PRODUCT_BUNDLE_IDENTIFIER)`，必须由与当前 Team、Bundle ID 匹配的 Mac App Development provisioning profile 授权。普通 ad-hoc 构建继续使用原有 entitlement，因此不会因为可信身份功能而要求开发者证书。

首次准备本机开发签名时：

1. 在 Xcode 的 Accounts 中登录 Apple Account，并为 Personal Team 创建完整的 Apple Development 身份（证书及其私钥）。
2. 复制 `DeveloperSigning.xcconfig.example`，填写本机 Team ID 和唯一、稳定的 Bundle ID。
3. 打开 `macos/Runner.xcworkspace`，在 Runner 的 Signing & Capabilities 中保持 Automatically manage signing，选择同一 Team，并在本机执行一次 Build/Run。Xcode 会创建或下载与 Keychain Sharing entitlement 匹配的开发 provisioning profile。
4. 重新执行 `flutter build macos --debug`。构建产物必须同时包含 `com.apple.application-identifier`、`com.apple.developer.team-identifier` 和预期的 `keychain-access-groups`；缺少任一项都应失败关闭，而不是改用软件私钥。

只有证书文件而没有对应私钥不构成有效签名身份；`security find-identity -v -p codesigning` 必须至少返回一条有效的 Apple Development identity。`-34018` 表示运行中签名没有获得所需 Keychain entitlement，不能通过删除 `kSecUseDataProtectionKeychain` 或退回普通文件密钥绕过。

iPadOS 使用相同的 v3 application tag、硬件检查、根指纹固定、认证子密钥轮换和签名自检规则。iPad 真机上的应用必须由稳定 Personal Team/Apple Development 身份签名；模拟器没有 Secure Enclave，只用于构建和 Rust FFI 链接验证，可信入口按失败关闭处理。旧 v1/v2 软件身份只触发 `migrationRequired`，必须由用户明确替换。

由于 Secure Enclave 不能导入已有私钥，从旧软件根身份升级必然生成新的根公钥和机器码。没有可信记录时可由用户直接确认升级；已有可信记录时必须先撤销，再通过动态连接码重新配对。旧根身份不得通过自签迁移自动继承授权，避免已泄露的软件密钥劫持新身份。

机器码 v2 从根公钥 SHA-256 指纹截断并附加校验得到，只承担路由和展示作用，不是密码。认证时必须校验完整根公钥指纹，不能只比较机器码文本。

## 首次配对

首次信任复用已建立的连接码 WebRTC 会话：

1. 双方交换根公钥、认证子密钥证书和各自随机数。
2. 双方基于会话 ID、根公钥指纹和随机数计算相同的六位 SAS 校验码。
3. 两端展示 SAS；Host 暂停远程输入，避免控制端代替本机用户确认。
4. Host 选择授权范围：查看屏幕为必选，键鼠、剪贴板、文件传输和自动续期分别控制。
5. 双方分别用根密钥签署包含最终权限位的确认内容。
6. Host 验证双方确认后签发方向明确的 pending `TrustGrant`，先通过 Rust 统一校验时间、签名、身份和权限，再写入本机加密 pending 事务。
7. Controller 使用同一 Rust 校验入口验证 Grant，按 `(pairingSessionId, grantId)` 幂等保存 pending，并返回根密钥签名的 `grant-accepted` 回执。
8. Host 验证接受回执后才将本地 pending 提交为可信记录，并返回签名的 `pairing-committed` 回执。
9. Controller 验证提交回执后才将本地 pending 提交为可信记录。任一端都不能在收到对端签名确认前显示“可信关系已建立”。

任何身份变化、SAS 不一致、签名错误、权限内容变化、拒绝、断线或超时都会终止配对并清除未提交事务。重复消息只能幂等重放同一事务，不能更换 Grant 或权限。

## 可信直连

控制端从本地可信列表选择 Host 后，通过机器码请求临时路由：

1. Java 为在线 Host 与 Controller 建立临时 `sessionId`，并与连接码会话共用单控制端仲裁。
2. Host 发送签名挑战；Controller 使用已持有的 `TrustGrant` 和签名响应。
3. Host 校验固定根身份、认证子密钥证书、授权有效期、撤销状态、请求权限、nonce、序列号和接收者指纹。
4. 双方交换签名 Offer/Answer，并生成同一份 `TrustedSessionBinding`；该 transcript 固定双方 nonce、权限、认证子密钥、Offer/Answer 哈希和双方 SHA-256 DTLS fingerprint。
5. 双方在 Rust 中冻结 nonce 和认证子密钥上下文；上下文只能以完全相同的值幂等重放，任何替换、空值、伪造 P-256 公钥或空 transcript 哈希都会失败关闭。会话期间认证子密钥不得切换。
6. Host 先验证签名绑定并成功应用 Answer，Controller 再验证 Host 对同一 binding 的确认；双方 Rust 状态机均进入 `Authorized` 后，才开放采集、输入和数据通道功能。

签名信封使用 60 秒有效期、单调序列和一次性 nonce。防重放缓存有界，缓存耗尽时失败关闭并要求重建会话。原始签名 payload 上限为 32 KiB，为 Java 64 KiB JSON/WebSocket 上限预留 Base64、身份和签名开销。

连接码与可信路由共用 `HostSessionArbiter`：一个 Host 同时只能被一个 Controller 占用。Host 忙时不能消费仍有效的连接码。

## 权限与生命周期

`TrustGrant` 默认只有“查看屏幕”和“控制键鼠”，剪贴板与文件传输需要 Host 明确授权。运行期每条敏感链路继续检查授权，不因媒体会话已经建立而放行。

| 项目 | 默认值 | 行为 |
| --- | --- | --- |
| 签名会话票据 | 60 秒 | 超时或重放立即拒绝 |
| 最大时钟偏差 | 30 秒 | 只允许 `issuedAt/notBefore` 最多来自未来 30 秒，不延长任何过期时间 |
| 认证子密钥 | 30 天 | 自动轮换，旧子密钥最多重叠 7 天 |
| 可信软租约 | 90 天 | 自动续期开启时，于剩余 14 天内在成功可信会话后续期 |
| 人工复核硬期限 | 365 天 | 不能自动越过，必须重新使用连接码配对 |

续期只能保留或缩小权限，不能改变根身份、扩大权限或延长原始硬期限。全局“暂停可信连接”和单设备撤销会立即执行本地门禁；活动可信会话会断开，动态连接码会话不受影响。

授权失效通过独立的进程内事件流通知所有活动会话。暂停为全局失效事件；撤销事件同时携带设备根指纹、当前授权 ID 和仍在重叠期内的旧授权 ID。命中的会话先关闭媒体、输入和数据通道，再进入失败状态，不能只更新设备列表后继续使用已有连接。

可信设备记录、授权、撤销墓碑、暂停状态和审计详情保存在 AES-GCM 加密 SQLite 中，数据库密钥由系统安全存储提供。审计记录配对、可信连接、续期、权限变化、过期和撤销，不记录私钥、签名原文、屏幕内容或剪贴板内容。

## 能力与兼容

可信链路通过以下能力协商隔离：

- `device-identity-v1`
- `trusted-device-auth-v1`
- `signed-webrtc-binding-v1`
- `trust-lease-renewal-v1`
- `trusted-pairing-transaction-v1`

新字段缺失即关闭对应能力。缺少 `trusted-pairing-transaction-v1` 的客户端不能创建新可信关系，但仍可继续使用动态连接码；可信直连不得因对端缺少能力而自动降级。

## 验收清单

当前自动化门禁已覆盖签名证书、授权权限与期限、nonce/序列重放、不可变 WebRTC 上下文、异常 P-256 公钥、空 transcript 哈希、暂停/撤销事件和真实 macOS Rust FFI。下面仍以跨设备物理验收结果作为最终发布标准。

- [ ] Mac、Windows、iPad 两两使用连接码配对，SAS 一致后才能生成可信记录。
- [ ] 篡改任一根公钥、SAS nonce、权限位、签名 SDP、接收者指纹、序列或有效期，连接均失败关闭。
- [ ] 两端时间差在 30 秒以内时配对成功；超过 30 秒显示“检查自动设置日期与时间”，不能误报为授权过期。软、硬过期边界不得因 30 秒容差延后。
- [ ] 在 pending、accepted、committed 任一步断线、拒绝或超时，未提交端均不出现可信记录；重复相同回执幂等，不同 Grant ID 或内容必须失败关闭。
- [ ] 同一签名消息重放 100 次均被拒绝，不能产生第二条会话或重复续期。
- [ ] 更换局域网信令地址后，原可信关系仍可直连；假冒相同机器码但不同根公钥的设备必须被拒绝。
- [ ] 可信直连连续 100 次；任何失败都不得自动改用连接码。
- [ ] 暂停全部可信连接、撤销单设备和软租约过期后立即拒绝新连接，并终止对应活动可信会话。
- [ ] 自动续期不扩大权限、不越过 365 天硬期限；关闭自动续期后 90 天到期必须重新配对。
- [ ] Host 已有连接码或可信会话时，另一认证方式返回忙；被拒绝的正确连接码仍可在 Host 空闲后使用。
- [ ] 可信授权没有剪贴板或文件权限时，相应通道保持关闭；动态连接码原有行为不回归。
- [ ] Windows 11 + TPM/CNG、macOS/iPadOS Secure Enclave 真机验证密钥不可导出、重装/密钥变化触发身份变化告警。
- [ ] macOS 旧式软件身份只显示为待迁移，应用不读取旧私钥；升级后根密钥和认证子密钥均由 Secure Enclave 恢复并通过签名自检。
- [ ] 模拟缺少稳定签名、Keychain 权限缺失或锁定、密钥条目缺失、根指纹不一致和 Secure Enclave 自检失败，均显示不同诊断且不自动降级。
- [ ] 将 Keychain 数据库或应用偏好复制到另一台 Mac 不能恢复 Secure Enclave 私钥；原设备重启应用后机器码和根公钥保持一致。
- [ ] 身份升级或重置后机器码发生变化，旧可信授权不能继续使用；动态连接码始终可用于恢复。

## 当前限制

- Windows 原生编译、TPM 行为和 Mac/Windows/iPad 跨平台物理验收必须在目标设备执行。
- iOS 构建阶段会分别生成真机 `aarch64-apple-ios` 及模拟器 `aarch64-apple-ios-sim`/`x86_64-apple-ios` 静态库，并显式保留 Dart FFI 使用的 C ABI；新开发机首次构建前需要安装对应 Rust targets。
- 当前 Java 可信路由是单 JVM 内存实现，适用于局域网开发；公网多实例需要 Redis 路由、分布式限流、TLS 和 TURN 临时凭据。
- 恶意信令服务器仍可拒绝服务或暴露元数据，但不能在没有设备私钥和有效本地授权的情况下伪造可信端点。
