# 被控端隐私屏

## 目标

远程会话建立后，被控端的本地显示器只显示固定提示画面，旁观者不能看到控制端正在进行的桌面操作；控制端仍接收真实桌面画面。该能力由被控端策略决定，控制端不能远程开启或绕过。

## 当前实现：标准隐私屏

标准模式适用于当前无需安装驱动的 Mac/Windows 桌面版本：

- 会话开始前，原生后端为每个活动显示器建立顶层、不可激活的隐私窗口。
- macOS ScreenCaptureKit 从采集内容中排除当前应用，因此隐私窗口不会进入远程画面。
- Windows 使用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`；不支持时仅回退到仍可从采集中隐藏窗口的 `WDA_MONITOR`。
- Flutter 会话层只有在“全部显示器均已覆盖且遮挡窗口已排除采集”后才启动桌面采集。
- 会话期间每两秒复核覆盖状态；显示器热插拔后原生层重建全部隐私窗口。覆盖失效或状态无法确认时，立即终止远程会话。
- 断开、失败和进程退出都会撤销隐私窗口；未完整激活时不会继续共享屏幕。

标准模式不拦截本机物理键鼠。隐私窗口本身忽略鼠标事件，避免破坏现有远程输入链路；由于普通用户态进程不能可靠区分物理输入和 `SendInput`，当前版本不宣称具备本地输入封锁能力。

## 安全边界

标准模式只覆盖当前用户的交互桌面，不能覆盖：

- Windows 登录、锁屏、UAC/Winlogon 安全桌面和其他用户会话。
- macOS 登录窗口、FileVault 解锁界面和其他用户会话。
- 操作系统或显卡驱动绕过窗口合成的特殊显示路径。

因此 UI 使用“标准隐私屏”而非“安全黑屏”。需要 Windows 登录前、UAC 和强本地输入封锁时，必须采用已签名的服务、Credential Provider 与 Indirect Display Driver 组成的增强模式；不能用未签名驱动或普通顶层窗口模拟。

## 状态与能力

本地能力通过 `standard-privacy-screen-v1` 声明。运行时状态为：

`inactive → preparing → active → restoring → inactive`

任何覆盖不足、采集排除失败或异常拓扑变化都进入 `failed`，并触发失败关闭。原生遮挡后端和 Flutter 会话协调器在同一串行生命周期内提交状态，不允许旧的显示器回调重新开启已关闭的会话。

## 后续增强模式

Windows 驱动级模式应作为独立能力实现：

1. 签名的系统服务持有会话和安全桌面生命周期。
2. Indirect Display Driver 创建仅供远程捕获的虚拟显示器。
3. 物理显示器切换到固定提示或关闭输出，远程采集虚拟显示器。
4. Credential Provider 支持登录前认证；服务处理 UAC/Winlogon 边界。
5. 驱动安装、升级、回滚和恢复必须经过 Windows Hardware Lab Kit 与签名发布流程。

macOS 不应承诺驱动级等价能力；标准覆盖与 ScreenCaptureKit 排除是当前可维护、可分发的方案。

## 验收清单

- 单屏与多屏连接前全部显示固定提示，控制端仍显示真实桌面。
- 新增、移除、旋转和改变缩放比例后，两秒内恢复完整覆盖；失败则断开会话。
- 控制端画面不得出现隐私窗口、主应用窗口或递归画面。
- 动态连接码与可信连接使用同一门禁。
- 连接失败、网络断开、应用退出后不残留隐私窗口。
- 隐私屏之外的视频、输入、音频、剪贴板和文件传输行为保持原样。
- Windows 安全桌面和 macOS 登录窗口明确显示为标准模式不支持，不得误报为已保护。
